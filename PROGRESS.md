- Синк вернётся в Этапе 4 как **opt-in** (только при активной группе), со **стабильным per-install ID** отправителя вместо изменяемого имени — это настоящий корень проблемы с `peer_data`

## Этап 4 — Группа + защищённый синк (+ синк лимита)
Обновлено: 2026-09-03 · ветка `stage4-group-sync`
Спека: `docs/superpowers/specs/2026-09-03-stage4-group-sync-design.md`
План: `docs/superpowers/plans/2026-09-03-stage4-group-sync.md`

> По решению пользователя Этап 4 **поглотил Этап 5**: синк лимита/периода owner→member
> сделан здесь же, отдельного Этапа 5 не будет.

### ✅ Сделано
- Стабильный `install_id` (`crypto.randomUUID()`, сид один раз) — self-guard при приёме данных; закрывает корень задвоения `peer_data` (долг Этапа 2)
- Чистый `src/main/group.js` (UMD + node:test): `generateCode` (6 симв. `A-Z2-9` без похожих), `normalizeCode`, `validateHandshake`, `isSelf`, `shouldApplyLimit`
- `src/main/peer.js`: `storePeerAggregates(db, payload, myInstallId)` — запись данных напарника с self-guard по install_id (покрыт sql.js-тестом)
- `src/main/sync.js` переписан: handshake `{type:'hello', installId, code}` при коннекте (обе стороны), несовпадение кода → `ws.close()`; payload с `installId/role`, у owner + `limit/period`; приём применяет лимит только `member`←`owner`; `startSync` идемпотентный + новый `stopSync`
- UDP-broadcast только для discovery (код по UDP не ходит)
- IPC `group:create` (owner+код+startSync), `group:join(code)` (member), `group:leave` (solo, код='', stopSync, wipe peer_data)
- Синк на старте приложения стартует **только при активной группе** (gated boot) — соло остаётся офлайн
- UI вкладки «Синхронизация»: соло (Создать группу / Присоединиться по коду) ↔ группа (роль, код, интервал, последняя синхр., Покинуть); индикатор в шапке снова активен
- i18n-ключи группы (ru/en); код выделяется/копируется, отступ кнопки поправлен

### 🧪 Тесты
- `npm test` (`node --test`) — 33/33 (i18n, пресеты, период, peer, roles, group)
- E2E между двумя инстансами (`--user-data-dir` A/B) вручную: create→join, синк часов, календарь, суммирование лимита, read-only лимит у member — подтверждено пользователем

### 💬 Решения
- Идентификация по install_id как self-guard; `peer_data` остаётся с ключом по имени (риск одинаковых имён в паре принят)
- Handshake-код закрывает пункт «Защита соединения» из банка идей на уровне, достаточном для домашней сети (HMAC/TLS не делаем)
- Leave чистит `peer_data` — возврат к чистому соло

### 📋 Следующий шаг
- Этапы универсализации завершены (1–4, Этап 5 поглощён). Обсудить: упаковка/релиз, либо пункты из банка идей

## UI redesign — прототип «Focus + Dashboard» (Максим)
Обновлено: 2026-09-16 · статус: **отложено / обсуждение**
Прототип: `ui-audit/prototypes/tt-prototype.html` (+ `README.md`), влит в `main` (PR #8)

> Максим предложил новое направление внешнего вида. Это **референс-мокап**, а не рабочий код:
> логика — заглушка, данные синтетические зашиты в разметку, синка/i18n/SQLite нет.
> Живёт отдельным standalone-HTML, наш Electron-код не затрагивает.

### 📐 Что в прототипе
- **Focus mode** — кольцо-таймер во весь экран (категория над временем, `сегодня Xh / Yh`, ряд «пилюль» категорий), canvas-фон (частицы/сияние/засветы), опциональный, глушится при `prefers-reduced-motion`
- **Dashboard** — левый рельс + бенто-сетка: общий лимит с раздельным вкладом двух участников + метка синка, «Сегодня» / «В среднем за день», пончик по категориям, столбцы по дням, таблица категорий; календарь и настройки — отдельные виды в рельсе
- **4 темы**: Emerald + Indigo, каждая в тёмной и светлой; палитра целиком в CSS-переменных (токенах)
- Переключение Focus↔Dashboard: кнопка **T** / **Ctrl+M**, круговая волна перехода (или Fade)

### 💬 Оценка для интеграции
- Соответствует исходному ТЗ (большая круглая зона таймера; dashboard с shared-лимитом; календарь)
- **Плюс переноса**: цвета — токены, 4 темы задают палитру целиком → перенос акцентной системы реалистичен; закрывает открытый вопрос «Светлая тема» из банка идей
- **Риск**: canvas-эффекты на слабом железе (Ryzen 5 4650U) — держать выключаемыми по умолчанию
- **Объём**: это большой визуальный скачок относительно текущего рабочего UI — тянет на отдельный многоэтапный этап, не на правку в лоб

### 📋 Не начато — открытые вопросы перед стартом
- Что берём: только палитру/токены и Dashboard-раскладку, или весь Focus-режим с эффектами?
- Как ложится на существующий i18n / роли / синк (реальные данные вместо заглушек)
- Разбить на подэтапы (токены-темы → dashboard-раскладка → focus-режим → эффекты) по нашему инкрементальному подходу

## Упаковка (electron-builder)
Обновлено: 2026-09-03

### ✅ Сделано
- Сборка NSIS-инсталлятора через `npm run build`
- Конфиг сборки: `assets/` включены в `files`, `asarUnpack` для WASM sql.js
- `electronDist` указывает на локальный бинарник — не нужен интернет для загрузки Electron

- База данных хранится в `AppData\Roaming\time-tracker\` — сохраняется между переустановками

### 💬 Решения / нюансы
- `winCodeSign` нужно скачать один раз вручную (браузером) если `app-builder.exe` заблокирован фаерволом
- Ранее сборка требовала прав администратора (симлинки при распаковке winCodeSign); в релизной сборке 2026-09-03 проблем не возникло
- Известный нюанс: `\r\n` в `node_modules/electron/path.txt` мог ломать `npm run dev` после сборки — при релизной сборке файл остался корректным (`electron.exe`)
