# Универсализация Time-Tracker — дизайн

Дата: 2026-09-02
Статус: согласовано, готово к плану

## Цель

Убрать хардкод под двух конкретных пользователей (Саша/Максим) и превратить
приложение в универсальный продукт для open-source / портфолио. Любой
пользователь настраивает своё имя, работает в одиночку по умолчанию и может
опционально создать группу-пару для шаринга лимита и синхронизации часов по LAN.

## Продуктовая модель

- **Соло-режим — дефолт.** После первого запуска приложение работает для одного
  человека: свой лимит, свои категории, без сети.
- **Опциональная группа = пара (ровно 2 участника).** Один создаёт группу и
  становится владельцем (owner), второй присоединяется по коду (member).
- Размер группы в этой версии — строго 2. Mesh на N участников не делаем (отложено).

## Роли

Ключ `group_role` в `settings`:

| Роль     | Лимит/период      | Синк | Как получить                     |
|----------|-------------------|------|----------------------------------|
| `solo`   | свой, редактируем | нет  | дефолт после первого запуска     |
| `owner`  | свой, редактируем | да   | «Создать группу»                 |
| `member` | read-only от owner| да   | «Присоединиться» по коду         |

- Гейт редактирования лимита теперь по роли (`owner` может, `member` — нет),
  а НЕ по имени. Удаляется текст «Изменить настройки может только Максим».
- В соло общая шкала прогресса — это личный лимит. В паре — общий лимит owner'а
  против суммы часов обоих участников.

## Первый запуск

- Экран выбора «Саша/Максим» заменяется на **поле ввода имени**.
- Поле префиллится именем из системы (`os.userInfo().username`), пользователь
  может стереть и ввести своё.
- Сохраняется в `settings.user_name` как есть; отображается как есть (маппинг
  `currentUser === 'Sasha' ? 'Саша'` удаляется).
- После ввода имени — сразу соло-режим (`group_role = 'solo'`).

## Группа: Create / Join (вкладка «Синхронизация»)

- **Создать группу**: приложение генерирует короткий код (например, 6 символов).
  Код становится общим секретом. Роль → `owner`. Синк запускается.
- **Присоединиться**: пользователь вводит код. Роль → `member`. Синк запускается.
- **Покинуть группу**: роль → `solo`, код очищается, синк останавливается.
- Существующие настройки вкладки (интервал синка, время последней синхронизации,
  статус-индикатор) остаются, но актуальны только когда группа активна.

## Сетевой слой (`src/main/sync.js`)

- Синк **не стартует автоматически** при запуске приложения. Стартует только при
  активной группе (`group_role` ∈ {owner, member} и есть `group_code`).
- **Handshake по коду**: при установлении WS-соединения первым сообщением
  передаётся `group_code`. Несовпадение → соединение отклоняется/закрывается.
  Это закрывает дыру «любое устройство в сети может подключиться».
- UDP-broadcast остаётся только для обнаружения peer'а (адрес+порт). Код в
  открытом виде по UDP НЕ передаётся — валидация только в WS-handshake.
- **Синхронизация лимита/периода**: в payload добавляются `limit` и `period`
  (`period_start`, `period_end`), когда отправитель = owner. Member сохраняет их
  в свои `settings` (read-only). Сейчас лимит не синкается — это новая часть.
- Пара строго на 2: один исходящий `peerSocket`, один код на двоих. Модель
  соединения не переписывается.
- Порты 43210/43211 остаются константами. Вынос в настройки — отложено (YAGNI).

## i18n (ru + en)

- Инфраструктура: `src/renderer/js/i18n/ru.js` и `en.js` (плоские словари
  `key → строка`), функция `t(key)` и применение переводов по атрибутам
  `data-i18n` в HTML при загрузке и при смене языка.
- Язык хранится в `settings.lang`. Дефолт по локали ОС: русская локаль → `ru`,
  иначе `en`.
- Переключатель языка — в **новой вкладке настроек «Общие»**.
- Строки главного процесса, попадающие в UI (напр. диалог «О программе»),
  переводятся на стороне renderer.

- `src/renderer/js/app.js`:
  - маппинг имени в строках ~344, ~382, ~384 → имя из `user_name` как есть.
- Гейт редактирования лимита → проверка `group_role === 'owner'`, не имени.

## Этапы реализации (последовательно)

1. **Инфраструктура i18n** + вынос существующих строк в словари ru/en, вкладка
   «Общие» с переключателем языка. Фундамент — дальше всё на ключах.
2. **Первый запуск**: поле имени вместо выбора Саша/Максим; универсальные пресеты
   с учётом языка.
3. **Роли** `solo/owner/member`: ключ `group_role`, переделка гейта лимита,
   поведение шкалы в соло.
4. **Create/Join группы** в настройках + handshake по `group_code`; синк
   стартует только при активной группе.
5. **Синк лимита/периода** owner → member.

Каждый этап — отдельная итерация: собрать, проверить, потом следующий.

## Явно НЕ входит (YAGNI / отложено)

- Группы >2 участников (mesh).
- Настройка портов синка в UI.
- Полноценная криптоаутентификация (HMAC/TLS) — пока достаточно проверки кода
  в handshake.
- Миграция существующих БД Саши/Максима — новые установки доминируют; отдельная
  миграция аватаров не нужна (аватары уже кейнятся по `user_name`).
