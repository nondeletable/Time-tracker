# Этап UI-1 — токенизация палитры — дизайн

Дата: 2026-09-17
Статус: согласовано, готово к плану
Ветка: `stage-ui1-tokens`

## Контекст

Максим предложил новое визуальное направление (прототип
`ui-audit/prototypes/tt-prototype.html`, влит в `main`). Прототип целиком построен
на семантических CSS-токенах и поддерживает 4 темы (emerald/indigo × dark/light).

Текущий `src/renderer/css/style.css` (1467 строк) содержит **46 захардкоженных
цветов** и не имеет токен-системы (`var()` используется только для
пользовательского `--cat-color`). Плюс в `src/renderer/js/app.js` захардкожены
**3 интерфейсных цвета** в логике общей шкалы.

Интеграция прототипа разбита на этапы. Это — **первый**: ввести токен-слой как
фундамент под темы. Сами темы — следующий этап (UI-2).

## Цель

Перевести всю **интерфейсную** палитру на семантические CSS-токены **без
изменения внешнего вида**. Структура и имена токенов совместимы с прототипом,
чтобы этап UI-2 сводился к подмене значений токенов.

Не в скоупе: темы, переключатель тем, любые изменения раскладки/разметки.

## Продуктовые решения (согласовано)

- **Объём:** только токенизация. Одна текущая тёмная тема, вид не меняется
  (вариант B из обсуждения).
- **Стратегия маппинга:** семантическая группировка (вариант A) — 46 сырых цветов
  → ~26 смысловых токенов. Близкие оттенки (Δ2–4 по каналу) схлопываются в один
  токен; это даёт микро-сдвиги, невидимые глазом, но кладёт слой в структуре
  прототипа.
- **`app.js` в скоупе:** 3 интерфейсных цвета логики шкалы тоже токенизируем.
- **Не трогаем:** цвета-данные категорий (`cat.color`, инлайновый `--cat-color`,
  заливка `stat-bar-fill` из `row.color`) и пресет-палитру выбора цвета
  `CAT_COLORS` (`app.js:479`) — это данные, а не интерфейсная тема.
- **Хранение токенов:** один блок `:root { … }` в начале `style.css`. Проект без
  сборщика, один CSS — отдельный файл токенов смысла не добавляет.

`--surface-*`, бордер → `--border-*`.

## Токенизация `app.js`

Три интерфейсных цвета в логике общей шкалы (`updateLimitBar`):
- `app.js:187` — заливка `#4ade80` (норма) → `--accent`
- `app.js:192` — заливка `#f87171` (превышение) → `--danger`
- `app.js:198` — текст времени `#5a5a7a` (норма) / `#f87171` (превышение)
  → `--text-faint` / `--danger`

**Подход:** логика «превышено/нет» переезжает в CSS-класс. JS переключает класс
`.over` на `#limit-bar-fill` (и/или обёртке), а цвета заливки и текста задаются в
`style.css` через токены:
```css
.limit-bar-fill        { background: var(--accent); }
.limit-bar-fill.over   { background: var(--danger); }
.limit-bar-time        { color: var(--text-faint); }
.limit-bar-time.over   { color: var(--danger); }
```
JS больше не пишет `style.background`/`style.color` для этих элементов —
только `classList.toggle('over', over)`. Ширина шкалы (`style.width`) остаётся в
JS (это не цвет). Заливка **категорий** (`stat-bar-fill` из `row.color`) не
меняется — там реальный цвет-данные.

## План работ (инкрементально, коммит на осмысленный кусок)

1. Добавить блок `:root` со всеми ~26 токенами (значения = текущие цвета).
   Ничего ещё не ссылается — вид не меняется.
2. Перевести `style.css` на `var(--…)` группами: поверхности → границы → текст →
   accent → danger. На каждой группе — визуальная сверка.
3. Перевести `app.js`: класс `.over`, цвета шкалы из токенов (CSS).
4. Починить `#6060808` (уже покрыто шагом 2 через `--text-faint`).

## Риски и обратимость

- Чисто визуально-стилевой этап; логика приложения не меняется.
- Единственные допустимые визуальные отличия: микро-слияния близких оттенков и
  фикс бага `#6060808`. Любое иное «поехало» — регресс, откат по коммитам.
- `getComputedStyle` не используется — цвета шкалы приходят из CSS-классов, а не
  читаются из JS, поэтому шкала автоматически станет theme-aware на этапе UI-2.
