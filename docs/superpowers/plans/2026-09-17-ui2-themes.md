# Stage UI-2 — Themes (emerald/indigo × dark/light) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add four themes (accent emerald/indigo × mode dark/light) from Maxim's prototype, switchable live in Settings, on top of the UI-1 token layer.

**Architecture:** `data-accent` × `data-theme` on `<html>`. Four two-attribute CSS blocks set Maxim's 11 anchor tokens verbatim per theme; the 15 derived tokens live once on `:root` as `color-mix()` over the anchors and recompute per active theme. `applyTheme()` sets the two attributes; two `<select>` controls in the "Общие" settings tab persist `theme`/`accent` and apply live, mirroring the existing language switch.

**Tech Stack:** Vanilla CSS (`color-mix`, Electron 31 / Chromium 126), vanilla JS renderer, sql.js `settings` via IPC, `node:test`.

Replace the entire contents of `test/no-hardcoded-colors.test.js` with:

```js
const test = require('node:test')
const assert = require('node:assert/strict')
const fs = require('node:fs')
const path = require('node:path')

const CSS = fs.readFileSync(
  path.join(__dirname, '..', 'src', 'renderer', 'css', 'style.css'),
  'utf8'
)

// Raw hex is allowed ONLY in custom-property definitions (--x: #hex), which
// includes the :root fallback and the per-theme anchor blocks. Anywhere else
// (color:/background:/border: …) colors must go through var(--…)/color-mix.
test('style.css uses raw hex only in custom-property definitions', () => {
  const offenders = CSS
    .split('\n')
    .map((line, i) => ({ n: i + 1, line }))
    .filter(({ line }) => /#[0-9a-fA-F]{3,8}\b/.test(line))
    .filter(({ line }) => !/^\s*--[a-z0-9-]+\s*:/.test(line))
    .map(({ n, line }) => `${n}: ${line.trim()}`)
  assert.deepEqual(offenders, [], `raw hex outside token definitions:\n${offenders.join('\n')}`)
})
```
